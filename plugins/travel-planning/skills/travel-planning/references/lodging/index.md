# 住宿研究入口

本文件是 `lodging.core` 的公共契约和住宿专项路由。普通住宿身份与衔接先按本文件完成；涉及动态报价、多人多房、自驾停车或深夜到达时，再读取 [库存与入住容量](inventory-and-occupancy.md)。

## 文件路由

| 文件 | 何时读取 | 重点 |
| --- | --- | --- |
| 本文件 | 所有住宿研究任务 | 实体身份、日期人数、位置衔接、入住规则和候选比较 |
| [inventory-and-occupancy.md](inventory-and-occupancy.md) | 查询动态价格或库存；两间以上；特殊床型；晚到；自驾入住 | 供应商能力边界、房量证明、报价引用、停车和前台失败备选 |

## 公共输入

- 入住、退房日期与连续住宿夜。
- 成人、儿童、房间数、床型、同住与分房要求。
- 每日片区、到达枢纽、首个活动、最后活动和行李路径。
- 预算、早餐、取消、支付、发票、无障碍和停车要求。

## 研究步骤

1. 核验实体：酒店完整名称、品牌或独立住宿、城市、行政区、具体地址、坐标和官方入口。
2. 核验位置：计算到到达枢纽、每日首末活动和离开枢纽的门到门路线，不用直线距离代替。
3. 核验入住：前台时间、证件、最早入住、最晚保留、退房、寄存和凌晨到达处理。
4. 统一价格口径：房型、入住人数、房间数、夜数、税费、早餐、支付和取消条件。
5. 比较候选：说明每个候选对路线、房间需求和预算的影响；最终住宿事件只绑定一个 `lodging_id`。

## 最小结构化产出

- `lodging_options[]`：稳定住宿身份、日期、房型需求、位置核验、报价引用和选择状态。
- `inventory_refs[]`：采用报价绑定具体快照和 offer。
- 与入住、退房、寄存或晚到相关的 `event_bindings[]`、`constraints[]` 和 `unresolved[]`。

## 完成门槛

- 全名、城市、行政区、地址和坐标经过一致性核验。
- 入住人数、房间数、床型和连续住宿夜与查询条件一致。
- 价格说明税费、早餐、取消、支付和按房/按晚口径。
- 未证明全部所需房间可订时，只称“报价候选”，不称“有房”或“已确认”。
- 到达、首末活动、行李与退房后的衔接可执行。
