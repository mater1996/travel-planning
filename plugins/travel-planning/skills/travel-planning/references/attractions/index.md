# 景点研究入口

本文件既是 `attractions.core` 的公共研究契约，也是景点类型文档的路由页。任何景点任务先读本文件，再只读取当前景点实际激活的类型 profile。

## 关联文件与读取条件

| 文件 | 适用对象 | 何时读取 | 主要新增判断 |
| --- | --- | --- | --- |
| [museum-venue.md](museum-venue.md) | 博物馆、美术馆、展馆、室内场馆 | 有闭馆日、分时预约、安检寄存或展厅顺序时 | 场次能否衔接、临展日期、闭馆前退出 |
| [scenic-area.md](scenic-area.md) | 大型景区、多入口、多分区景区 | 存在景交、索道、内部换乘或入口选择时 | 入口出口组合、内部交通停运后的缩线 |
| [mountain-outdoor.md](mountain-outdoor.md) | 山岳、徒步、峡谷、雪地、高海拔 | 路线受体力、天气、日落或地灾影响时 | 最晚下撤、装备、救援与恶劣天气备选 |
| [theme-park.md](theme-park.md) | 主题乐园、水乐园、大型游乐园 | 项目限制、排队、预约通行或演出会改变顺序时 | 开园策略、项目组合、闭园疏散 |
| [performance-night.md](performance-night.md) | 演出、夜游、灯光秀、固定场次夜景 | 有固定入场或散场时间、夜间返程风险时 | 场次、取票、散场接驳和取消规则 |
| [urban-walk.md](urban-walk.md) | 老街、古城、市场、步行街和多节点 Citywalk | 占用独立时间窗，或串联两个以上命名地点时 | 具体看点与动作、连续步行线、时长构成和退出点 |

类型可以组合。例如山顶夜游同时读取 `mountain-outdoor.md` 与 `performance-night.md`。不要仅因名称含“山”或“公园”就激活，判断应基于实际采用活动和运营结构。老街、市场或连续街区只要成为正式游览时段，就必须激活 `urban_walk`，不能退化为自由文本 note。

## 公共输入

- 已确认路线中的城市、日期、每日片区和可用时间窗。
- 人数、年龄、体力、无障碍、行李、预算和兴趣约束。
- 前后交通锚点、住宿位置和下一项硬时间。
- `research-profile.json`、assignment、依赖任务结果和任务模板。

## 公共研究步骤

1. 确认实体身份：规范名称、具体地址、坐标、官方主页、官方公告和预约入口，避免同名分馆或不同入口混淆。
2. 核验适用日期：开放日、营业时段、停止售票、停止入场、闭园、临时关闭和季节性运营。
3. 判断是否采用：说明当季看点、适合人群、普通游览时长、最佳时段与不采用的替代项，不用泛化“值得一去”。
4. 设计执行顺序：选定入口、出口和有稳定 ID 的 checkpoints；记录节点间移动、内部交通、必到项、可跳过项和最晚离开时间。
5. 拆分费用：基础门票、必需景交、可选体验与互斥套票分别记录，避免重复计入基线。
6. 处理预约：产品、日期、场次、人数、证件、放票规则、截止时间、官方操作入口和无票备选。
7. 绑定风险：把体力、天气、设备停运和下一段交通约束写到具体 checkpoint 或事件，不生成脱离动作的泛化提醒。

## 最小结构化产出

- `attractions[]`：稳定身份、官方信息、运营、入口出口、checkpoint blueprint、预约、费用和来源。
- `event_bindings[]`：把景点绑定到适用日期和偏好时段，但不替主 Agent决定完整日程。
- `constraints[]`：会阻断采用或改变时序的规则。
- `unresolved[]`：动态事实不可得时的复核时间、入口和下一动作。

## 完成门槛

- 开放、预约、价格、入口和安全规则有与字段匹配的官方或运营方来源。
- 每个采用景点都有可导航入口、退出方式、最晚离开时间和失败备选。
- checkpoints 能构成入口到出口的顺序，不只是景点内部清单。
- 类型 profile 的阻断项已经完成或明确写为 blocking unresolved。
- 社区内容只支持近期体验、拥挤、玩法和避坑，不能单独证明开放或安全。
