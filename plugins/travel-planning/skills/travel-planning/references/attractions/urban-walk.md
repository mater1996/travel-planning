# 城市漫游、老街与市场

## 何时读取

采用老街、古城、历史街区、步行街、市场、滨水街区，或由两个以上命名地点组成的 Citywalk 时读取。单一封闭景点仍按对应景点类型研究；只有一句路过提醒时不激活本 profile。

## 建模边界

- 占用独立游览时间窗，或串联两个以上命名地点的步行活动，必须建模为 `attraction`，不能写成带结束时间的 `note`。
- `note` 只承载某一时刻的提醒、背景或操作说明，不表示持续活动；自由留白使用 `rest`。
- 城市漫游可以由多条公共街道组成，但必须有一个可导航入口、一个明确出口和连续的步行顺序。
- 对应 `planning.attractions[]` 实体必须标记 `attraction_type: urban_walk`，供 audit 区分普通景点与城市漫游合同。
- 如果只能确认片区名，无法回答沿途具体看什么、做什么以及在哪里转向，就缩短或取消该活动，不用“慢走”“随便逛”填满时间。

## 研究步骤

1. 划定范围：确认街区边界、入口与出口，避免把距离较远、名称相近或互不连续的街道拼成一条路线。
2. 选择节点：研究至少两个有稳定名称和可定位身份的 checkpoints。每个节点说明现场对象、旅行者动作和建议停留时间，不只重复地名。
3. 串联路径：记录节点顺序、站间步行方向或道路名、预计分钟数、过街或坡度障碍，以及需要时的地图路线。
4. 说明特色：把建筑、城市史、地方生活、店铺类型、市场时段或夜景写到对应 checkpoint；泛化背景不能代替现场可观察内容。
5. 核验运营：公共街道可标记全天开放，但市场、展馆、院落、店铺或夜景仍分别核验适用日期和时段。不要用街道开放推断沿途商户营业。
6. 设计取舍：标记必达、可跳过、雨天替代、拥挤绕行、最晚离开和提前退出点。总时长应由各节点停留与站间移动相加得出。

## Checkpoint 最小内容

每个 checkpoint 至少包含：

- 稳定 `id`、顺序、起止时间、kind、名称和可定位查询词；
- 一句可验证的现场看点，回答“这里具体有什么”；
- 一句旅行者动作，回答“到这里具体做什么”；
- 与下一站的移动方式或转向提示；最后一站改为出口和后续衔接；
- `required`，以及可选节点被跳过时节省的时间或替代方案。

只有来源支持的节点才可写 narration。社区内容可说明人流、氛围、拍摄时段和近期体验，不能单独证明历史事实、营业时间或具体店铺身份；地点身份、地址和路线优先由官方资料与地图 POI 交叉确认。

## 完成门槛

- 入口、出口和所有采用节点可定位，顺序构成连续步行线。
- 至少两个 checkpoints 各自有具体看点与动作，不是地名清单。
- 事件总时长能由节点停留与站间移动解释，且包含可跳过项或提前退出方式。
- 市场、院落、场馆和具体店铺的动态营业信息各自有来源；无法确认的内容写复核动作，不按街区整体状态推断。
- 最终事件使用 `subtitle`、`details[]`、`tips[]` 和 `execution.checkpoints[]`；不写 renderer 不展示的 `description`。
