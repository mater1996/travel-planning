# 交通研究入口

本文件既是 `transport.core` 的公共契约，也是交通方式文档的路由页。任何城际、本地交通或 road-trip 任务先读本文件，再按实际候选与采用方式读取专项文件。

## 关联文件与读取条件

| 文件 | 何时读取 | 不能代替什么 |
| --- | --- | --- |
| [flight.md](flight.md) | 候选或采用方案含航班 | 不能用平台报价代替出票与运行确认 |
| [rail.md](rail.md) | 候选或采用方案含铁路、高铁、夜行列车 | 不能只写城市名，必须落实车站和接驳 |
| [public-transit.md](public-transit.md) | 采用公交、地铁、公共轮渡或官方接驳 | 不能只给地图总耗时，必须落实站口与末班 |
| [self-drive.md](self-drive.md) | 旅行者本人驾驶自有车或租赁车辆 | 不能用 `mode=car` 路线代替车辆、停车、补能和驾驶风险 |
| [car-rental.md](car-rental.md) | 自驾车辆通过租赁取得 | 它依赖 self-drive，只描述取得车辆还不构成自驾计划 |
| [charter-driver.md](charter-driver.md) | 采用包车加司机或司导 | 不是自驾，不要求旅行者驾驶资格与换驾计划 |
| [coach-ferry.md](coach-ferry.md) | 采用长途客车、轮渡、客船或岛际船班 | 不能忽略天气停航、停止登乘和晚到接驳 |

同一交通边可读取多份文档。例如“航班抵达后机场租车自驾”应读取 flight、self-drive 和 car-rental；“高铁到站后地铁”应读取 rail 与 public-transit。

## 公共输入

- 准确日期、人数、行李、城市顺序、住宿和活动入口出口。
- 前一事件结束时间、下一硬时间、可接受缓冲、预算与舒适度。
- 候选方式及用户已经确认的路线边界。
- 动态来源快照、地图结果和官方运营规则。

## 公共比较口径

每条边统一从真实起点出口算到真实终点入口，并拆出：

- 到站、步行、等候、换乘、安检或边检、取行李与缓冲；
- 车上或飞行时间与完整门到门时间；
- 按人、按车或按房的费用口径，以及未计入项；
- 行李连续路径、首末班、停止办理和下一硬时间；
- 动态状态的查询时间、有效性和实际使用前复核点；
- 主方案失败后的替代方式、触发条件和增加的时间费用。

同一城际边由一个 `transport-intercity` 任务按相同日期、人数和门到门口径比较，不让航班与铁路分别给出互不相容的最终推荐。本地接驳由 `transport-local` 负责；车辆连续生命周期由 `road-trip` 负责。

## 最小结构化产出

- `transport_edges[]`：本地或门到门交通边。
- `intercity_options[]`：同一城际边的可比较候选。
- `route_anchors[]`：准确站点、出口、上车点、入口和坐标。
- `inventory_refs[]`：动态候选绑定 `snapshot_id + offer_id + role`。
- `event_bindings[]`：只表达候选适用日期与衔接，不替主 Agent做最终采用决定。
- 自驾时另由 road-trip 输出车辆、计划、租车与停车集合。

## 逐日连续性

- 交通研究按最终事件顺序覆盖每一条地点变化边，不只覆盖长距离或主要接驳。
- 步行几分钟仍是交通边；只要前一活动出口与后一活动入口不是同一坐标，就输出可绑定时间轴的 `transport_edge`。
- 每条边至少保存起终点名称与坐标、`distance_meters`、方式、门到门分钟或可显示时长、地图链接和备选。
- 景点内部 checkpoint、同一建筑内换层或前后锚点完全相同，可以由活动内部 instruction 表达，不重复生成交通事件。
- 正餐的双腿路线用于候选比较；主选确定后，进入餐厅和离开餐厅的实际腿仍要投影为逐日交通事件。

## 完成门槛

- 所有采用边都有准确端点、门到门时间、费用口径、行李处理、来源和备选。
- 每个采用活动都能由前一活动通过已采用交通边抵达；住宿日最后一条边闭合到住宿。
- 动态价格、库存与运行状态保持“查询时快照”，没有被写成已确认。
- 候选比较使用相同口径，差异和采用理由可复核。
- 专项文档的阻断项已完成，或形成带复核入口与时间的 unresolved。
