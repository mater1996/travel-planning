# 任务完成门槛

## 何时读取

创建 assignment 的 `completion_checks`、验收任务结果、决定是否接受 partial，或创建 gap task 时读取。只读本次任务域对应的小节。

## 景点

- 每个拟采用景点有坐标、实体地址、入口、出口，以及分开的官网、预约和公告入口。
- 有适用日期的开放、停票、停止入场、闭园、临时公告、费用与查询时间。
- 有入口到出口的 checkpoints；预约项目生成可绑定事件的 booking task。
- 微信公众号预约包含已核验公众号名、菜单路径和适用时官方说明文章。
- 社区内容只支持体验、拥挤与避坑，不覆盖官方事实。

## 城际与本地交通

- 开放式航班或铁路覆盖最早、最晚、时长、价格与推荐排序；结果落标准快照。
- 采用候选绑定具体 snapshot 与 offer；每条边有精确起终点、门到门时间、费用、备选和查询时间。
- 本地交通覆盖住宿、站点、景点出入口、主选正餐和返程锚点。
- 每个旅行日有可定位起点与终点；相邻地点不同的活动之间均有独立交通事件，且采用路线首尾与前后活动锚点一致。
- 中国境内地面交通有高德坐标和可执行链接；不虚构余票，包车明确资质、合同、行李与费用边界。

## 自驾与租车

- `road_trip_plans[]` 覆盖车辆、驾驶员、连续驾驶、道路限制、每个主要停靠点停车、油电补能和事故故障应急。
- 租车时 `rental_options[]` 覆盖取还车、驾驶资格、价格、押金、保险、里程、油电、异地还车与取消。
- `map_route.mode=car` 只能证明地图路线，不能单独通过自驾门槛。

## 住宿与餐窗

- 酒店按实际日期、人数、房间、床型和连续入住夜查询并落快照，采用候选绑定具体 offer。
- 酒店身份按全名、城市、行政区、地址和坐标核验；未验证多间同房型库存时只称报价候选。
- 每个住宿夜有候选或明确片区锚点，退房到入住的大件行李有归属。
- 每个完整旅行日有带前后锚点、预算、绕行上限与饮食约束的午晚餐窗。

## 餐厅

- 正常正餐有 2 至 3 个实体候选；受限场景提供有来源的例外和应急补给。
- 每餐声明 `meal_intent`；每个候选有近期社区证据驱动的 `value_assessment`。
- `route_worthy=true` 至少由两条近期独立社区来源支持，并进入 `route_influence`；需要重排时必须先由主 Agent 复核路线。
- 每个候选有地图 POI、动态快照、平台信号、合法可视证据和同口径双腿路线；距离未知不能提交最终 ranking。
- 主选、至少一个备选和切换条件明确。

## 天气与行前就绪

- 每个日期有天气状态或未来复核时间、固定图标、天气入口与查询时间。
- 天气影响绑定景点、交通或 checkpoint，并转成缩短、取消、改时、换交通或切换备选的动作。
- 节假日、行李、特殊人群、证件入境、保险通信与重要动态项目都有对象、截止或复核节点。
- 所有 `to_recheck` 项有真实 HTTPS 操作入口和明确待核字段。

## 停止条件

- 登录、验证码、平台风控或访问限制阻止查询时停止该来源，记录失败类型并采用合法替代入口。
- 动态价格或库存无法核实时标记待复核，不高频重试，不把不可得改写为无库存。
- 用户改变日期、人数、出发地或路线时，使受影响任务及下游 assignment 失效。
- 无法满足 blocking 条件时提交 partial 或 blocked，并明确缺失字段、原因、下一动作和责任方。
