# 页面结构与信息层级

## 何时读取

调整 renderer 的内容结构、默认视图、事件卡、一览表或路线图时读取。只改交互状态时转到 `page-interactions.md`。

## 顶部与全局

- 顶部显示路线、日期、人数、预算策略和最后核验时间，不复制逐景点费用、逐段交通与逐日天气。
- 默认详细行程，另提供“行程一览”和“路线图”。三种视图共用同一内容容器，切换时不横向跳动。
- 顶部后直接进入逐日时间轴，不再放规划说明或全局假设卡；改变执行的约束回到对应事件。
- 日期是时间轴一级节点，事件时间是二级节点；不增加粘性日期标签或滚动高亮导航。

## 详细时间轴

时间轴按真实执行顺序回答几点到、从哪里进入、如何移动、何时离开、多少钱、需要什么预约和失败时切什么备选。

- 核心字段使用定义列表或表格；Tag 只表达需预约、可选、待复核等辅助状态。
- 开放、停止入场、入口、内部顺序、交通、门票和费用默认展开，不能藏入“查看详情”。
- 景点卡顺序为标题与时长 → 开放与预约 → 景区内怎么玩 → 注意事项。
- 内部 checkpoints 使用嵌套时间轴；入口并入首节点，出口和最晚离开并入末节点。只有真实研究到的看点才显示 narration。
- 天气图标放景点卡右上角，至少 44×44px，有 aria label、摘要 tooltip 与实际天气入口；没有入口则省略。
- 交通卡显示精确起终点、线路或车次、门到门耗时、费用、换乘、推荐理由与备选。未来页面不展示当前拥堵或实时状态噪声。
- 交通卡同时显示距离；短途步行也作为相邻活动之间的交通节点出现，不能只埋在餐厅候选卡、活动描述或路线图中。
- 住宿卡显示入住日期、片区或酒店、价格状态、行李与下一站耗时。

## 城市漫游与自由时间

- 老街、古城、市场、步行街和多节点 Citywalk 使用景点卡，而不是只有标题的 note 卡。
- 卡片顶部用 `subtitle` 概括这段街区的主题；“景区内怎么玩”按 checkpoint 展示地点、起止时间、现场看点 `narration` 和旅行者动作 `instruction`。
- 标题中的“慢走”“逛街”“Citywalk”不能代替内容。页面必须让旅行者看出从哪里进入、依次看什么、怎么走、哪里可以跳过、最晚在哪里退出。
- `note` 不渲染为持续活动；自由留白使用 `rest`，并说明休息片区或与下一段的衔接。

## 餐饮卡

- 事件先显示 `selected_candidate_id` 的综合推荐，再以固定卡宽横向列表显示 `fallback_candidate_ids` 的完整备选卡。
- 主选与备选都可展开/收起；不能退化为链接条、窄网格或页内重新排序。
- 每张卡显示地址、特色菜、平台评分与评价量状态、近期社区证据或搜索入口、营业、两腿路线与高德门店入口。
- 两腿路线标题直接使用“起点名称 → 终点名称”，同时显示双方地址、距离与门到门时间；不另重复同名路线按钮。
- 不展示内部评分、加分拆解、长篇选择理由、“选择这家”或“已选为本餐”。
- 每餐保留一个以上一锚点为中心的“在高德查看附近餐厅”，与主选门店入口放在同一操作区。

## 行程一览

一览使用小字号、紧凑行高和表格线，固定为“时间 / 地点 / 关键信息”三列，日期为跨列分组行。只保留会改变执行的信息，不复制图片、地图、来源、按钮和研究字段。

窄屏仍保持表格语义，放入可聚焦横向滚动容器，不拆成卡片。

## 路线图

路线图按日期读取 `planning.daily_routes[]`，每一天只显示一条完整有序路线。站点覆盖住宿出发、景点、主选正餐、其他停靠点与结束点，并显示编号站点带。

每日标题区显示 `start_anchor → end_anchor`，让旅行者先确认当天从哪里开始、在哪里结束。路线图 stop 的 `event_id` 必须覆盖详细时间轴中的所有地点活动。

导览图默认用驾车方式串联顺序，仅用于快速感知；分段公交、步行或打车方式以详细行程为准。没有完整路线时显示明确空状态，不以部分路线冒充全天路线。

## 汇总

预算从事件费用派生；待办、每日强度和复核提醒都引用实际对象与时间。信息来源与页脚只在详细视图需要时展示，路线图视图不混入事件详情。
