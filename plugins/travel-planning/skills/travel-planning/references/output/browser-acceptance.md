# 浏览器与交付验收

## 何时读取

renderer、Vue 源码、编译资源、页面结构、交互或响应式规则发生变化后读取。纯研究内容更新不需要完整浏览器回归。

## 静态与单元检查

- 运行 renderer 与页面相关单元测试。
- 生成真实 itinerary HTML，不只测试空壳模板。
- 从 HTML 提取内联 JavaScript，执行 `node --check`。
- 验证无脚本状态仍包含日期、事件、预约、费用、路线外链与信息来源。
- 检查源码、编译资源、渲染器和安装缓存版本一致。

## 桌面浏览器

在真实浏览器验证：

- 详细、一览、路线图切换与键盘行为；
- 筛选清除后顺序恢复；
- 景点 checkpoint、餐厅卡和备选轮播展开/收起；
- 公众号复制、官方入口、门店、天气与路线外链；
- 地图只在接近视口时加载一次，全屏与 Esc 正常；
- 每日路线包含全部 `via[n]`，站点带与地图顺序一致；
- 打印预览没有遮挡、被截断的关键内容或交互残留。

## 移动端

至少验证 390px 宽度：

- 页面 `scrollWidth` 不超过视口；唯一允许横向滚动的是明确设计的一览表与餐厅轮播容器。
- 触控目标至少 44×44px，焦点与可访问名称完整。
- 餐厅卡保持固定可读宽度，不被挤成多列。
- 每日完整路线不因移动端 URL 降级而丢失途经点。
- 长标题、价格、地址与路线不会覆盖按钮或撑破容器。

## 交付门槛

- audit 的 `blocking=[]`；
- 浏览器无未处理异常；
- 核心外链均为 HTTPS 且目标与标签一致；
- 单文件 HTML 离线可读，外部服务失败不破坏核心行程；
- JSON、audit 与 HTML 来自同一研究摘要和 reviewed plan。
