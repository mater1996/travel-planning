# 行前就绪与横切场景

## 何时读取

路线进入可执行规划、最终交付或接近出发需要建立复核时间线时读取。它汇总跨领域风险，不替代交通、景点、住宿或餐饮的专项研究。

## 横切检查

- 节假日、地方活动、施工、临时公告和季节性停运。
- 行李从出发到入住、退房到离开的连续路径。
- 儿童、老人、无障碍、孕妇、慢病与过敏等具体约束。
- 证件、签证、过境、保险、货币、通信、时区与紧急联系。
- 服装、鞋、雨具、防晒、保暖、药品和户外装备。
- 预订、开售、免费取消、付款和最终复核的截止时间。

## 绑定原则

每项准备必须绑定实际对象或事件：

- 儿童座椅绑定车辆或租车候选；
- 雨雪装备绑定户外 checkpoint；
- 行李寄存绑定酒店、车站或活动入口；
- 末班交通绑定具体散场事件；
- 多房库存复核绑定住宿 offer。

不要生成“注意天气”“注意安全”“提前预约”这类没有对象、时间和动作的提醒。

## 复核时间线

- T-14：证件、预约开放、跨境要求、长周期装备和可取消订单。
- T-7：天气趋势、景区公告、道路与场次、住宿和主要交通。
- T-3：动态营业、停车、接驳、菜单、临时关闭与备选。
- T-1：班次运行、最终天气、门店临休、二维码或证件准备。
- 当日：只复核真正需要实时判断的运行状态，不把当前拥堵噪声提前写进长期页面。

具体时间点应根据产品规则和旅行日期物化，不能机械套用。

## 结构化产出

`readiness[]` 每项包含对象、状态、截止或触发时间、下一动作、来源、action link 和失败规则。不适用项明确 `not_applicable`。

## 完成门槛

- 所有会阻止出发、入场、乘车、入住或安全执行的事项都有负责人和复核节点。
- 动态项的复核时间合理，没有把查询时状态冒充未来确认。
- 失败规则能指向具体备选，不只提醒用户自行处理。

交通、景点、住宿和餐饮的专项复核由本次激活的领域 profile 定义；任务验收按[完成门槛](../orchestration/completion-gates.md)读取对应小节。
