# 证据与动态事实

## 何时读取

任何研究任务需要选择来源、保存动态事实、处理冲突、解释不可得状态或生成 action link 时读取。

## 来源职责

| 来源类型 | 可以支持 | 不能单独支持 |
| --- | --- | --- |
| 政府、景区、运营方、航司、铁路官方 | 开放、规则、资质、安全、正式通知 | 查询时第三方价格或社区体验 |
| 供应商与预订平台 | 查询时价格、库存候选、班次或运行返回 | 已锁价、已出票、已预订 |
| 地图与 POI | 实体位置、地址、坐标、路线与导航 | 营业承诺、预约成功、官方推荐 |
| 社区原帖 | 近期体验、玩法、拥挤、排队和避坑 | 开放、价格、资质、安全和库存 |
| Agent 计算 | 估算时间、预算汇总和排序判断 | 未经来源支持的事实 |

## 动态事实契约

价格、库存、班次、营业、天气、道路和运行状态至少记录：

- 查询条件与适用日期；
- `checked_at` 与需要再次复核的时间；
- 来源 URL 或标准快照引用；
- `verified`、`platform_reported`、`estimated` 或 `to_recheck` 等状态；
- 变化后会触发的动作或备选。

供应商完整响应先标准化为 `travel-source-snapshot/v1`。行程对象只保存 `snapshot_id + offer_id + role`，不得透传 Cookie、凭证或供应商私有响应。

## 冲突处理

按以下顺序判断，而不是简单选择最新或最高评分：

1. 是否支持当前字段；
2. 是否覆盖本次适用日期、分店、站点或产品；
3. 来源权威性；
4. 查询时间和公告生效时间；
5. 信息是否足够具体。

无法裁决时保留冲突，写明采用哪一项、原因、风险和下次复核，不静默覆盖。

## 不可得与失败

- `no_results` 只表示查询成功但结果为空。
- 鉴权、限流、网络、解析或工具失败使用错误结构，不伪装为空结果。
- 动态字段不可得时提供真实复核入口、查询条件、`recheck_at` 和 fallback。
- 无来源支持的估算必须显式标记估算方法和范围。

## 表述边界

- 报价候选不写成已锁价、有票、有房或已预订。
- 平台显示不写成官方确认。
- 多条社区帖子不自动升级成官方事实。
- action link 的标签说明平台、对象和待核字段，不只给无关首页。

需要调用供应商、生成手工入口或区分工具错误时，按需读取[实时数据工具入口](../tools/index.md)，失败场景只追加 `fallback-and-errors.md`。
